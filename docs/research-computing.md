# Research Computing (PhD/CS Research)

`workstation research doctor` verifies the toolchain below is installed
(WSL/Linux and macOS - installed via `platform/{linux,macos}/
install-research-tools.sh`, run from each OS's `bootstrap.sh`; Windows
dispatches into WSL, matching `security`, since governed projects live
under WSL's `~/src/*` per policy).

## Toolchain

| Tool | Role |
|---|---|
| TeX Live (Linux/macOS) / MiKTeX (Windows, native) | LaTeX distribution |
| Pandoc | universal document converter, the substrate under most modern authoring pipelines |
| [Quarto](https://quarto.org) | combines code + prose into one reproducible document (`.qmd` -> PDF/HTML/Word via Pandoc + LaTeX) - the more standard choice in 2026 than raw LaTeX+bibtex for anything that mixes analysis with writing; raw LaTeX still dominates pure math/theory papers and venue templates (ACM/IEEE/NeurIPS `.cls` files) |
| [pixi](https://pixi.sh) | reproducible scientific environments - the 2026 recommendation over raw conda/mamba for *new* projects (unifies conda-forge + PyPI + non-Python deps in one project-local lockfile); `research-python`'s existing pip-based setup is left as-is, not migrated |
| biber/latexmk | biblatex backend + build automation |

MiKTeX rather than TeX Live on Windows specifically (confirmed with Andrew):
no clean winget-native TeX Live path exists, and MiKTeX (auto-installs
packages on demand, smaller footprint) is the Windows-native standard anyway
- the same documents compile fine on either, only the package-manager
plumbing underneath differs.

## `research-paper` template

`workstation project init research-paper <name>` scaffolds the standard
convention: `paper/main.tex` + `paper/refs.bib` (biblatex/biber), `paper/
figs/` + `paper/tables/` (generated by `code/` scripts, never hand-edited),
`data/`, and a `Makefile` (`make paper` -> `paper/main.pdf` via `latexmk`).
Quarto is also available in the same Dev Container if you'd rather write
`.qmd` instead of raw `.tex`.

## Reference management

[Zotero](https://www.zotero.org) has no official CLI - it's GUI-first.
Export your library to BibTeX (Better BibTeX plugin) for `paper/refs.bib`,
or automate it with [`pyzotero`](https://pyzotero.readthedocs.io) /
[`pyzotero-cli`](https://pypi.org/project/pyzotero-cli/) if you want
scripted access instead of manual export - both are opt-in additions to a
project, not part of the base toolchain.

## `research-python` vs `research-paper`

- `research-python` - a Python research/notebook environment (JupyterLab
  already included).
- `research-paper` - a LaTeX/Quarto paper-writing environment.

Use both together for a project that has real code/analysis AND a paper to
write - they're separate governed projects, not one template trying to be
both.
